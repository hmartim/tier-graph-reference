# Conformance results

This directory holds the machine-readable and human-readable output of the
conformance runner:

- `conformance-results.json` — full result document (one entry per case, plus
  the pinned specification version, per-class rollup, and declared normative
  alignment);
- `conformance-summary.md` — a human-readable summary table.

Both are regenerated by:

```bash
python scripts/run_conformance.py
```

## Why these two files are tracked

They are **committed**, unlike most generated output. The release cites them as
the executed evidence behind the reported conformance claims, and a citation
that points at a gitignored file is not a citation.

The usual objection — committed output goes stale and starts lying — is answered
by making staleness detectable rather than by hoping:

```bash
python scripts/check_results_current.py
```

re-runs the suite and fails if the committed files no longer match, ignoring only
wall-clock execution time and per-case durations. It also runs under `pytest`
(`tests/integration/test_reports.py::test_published_results_are_not_stale`), so a
change to the code or the fixtures that is not accompanied by regenerated results
turns the build red.

Any *other* output written here — ad-hoc runs, alternative grounding profiles —
remains gitignored.

## Workflow

After changing services, fixtures, or the report shape:

```bash
python scripts/run_conformance.py
```

then commit `results/` alongside the change.
